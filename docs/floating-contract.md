# Floating Record contract

Opt-in Accessibility adds a movable organic button beside the keyboard for an eligible focused editor. On-screen access disclosure precedes enabling. Microphone and visible recording-notification controls remain required; unknown OEM restrictions are explained once, never claimed as known grants.

An explicit tap starts local Record immediately; no key or network setup delays microphone start. Stop ends capture, retains audio, then makes the requested file-transcription attempt. Failed or interrupted audio stays in shared history for manual retry. A changed/hidden editor, lock, permission loss or owner close stops the session and retains recoverable data without retargeting or reconnecting.

A successful result may use `FinalTextInsertion` once on the captured API33+ input connection. Gates/caret/ownership are checked again after IO and before commit. Unconfirmed writes never retry or roll back. Unsupported fields/versions use Copy. No full-field replacement, Send, new target adoption or automatic insertion from recovered history occurs.

The compact setup, shared idle preview, count-limit action and persisted drag position are unchanged. See [onboarding](onboarding.md), [position](floating-position.md), [Record](immediate-record.md), [legacy data](record-only.md).
