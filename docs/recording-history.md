# VD008 recording history

The main screen is the recording surface: the organic control, centered Live/Record choice and essential session feedback. A persistent bottom sheet lip has a short handle and compact saved count. Both an upward swipe and an accessible tap open history, including with zero recordings. Settings retains the upper-right gear and contains key/floating-access setup. No written swipe/tap instructions, setup link, permanent transcript editor or full-width Copy/Clear row compete with recording.

History is a sequence of voice-message bubbles in the Soft Current milk/lavender and plum palette. One bubble contains a circular Play/Pause control, a sampled local waveform, duration below the audio row, compact time and an explicit transcript toggle at the right. Play, waveform and the right action share one vertical centerline; both icon controls are 48 dp circles. The sheet has no visible heading or Close button: the drag handle/downward gesture, system Back and an accessible dismiss action close it. Redundant Transcribed/Transcription failed labels are omitted. Text starts collapsed, including short transcripts; expanding reveals it inside the same message. Copy is small and next to the text. Message options exposes confirmed Delete and, for the current editable draft, Clear current text. Pending/failed audio replaces the transcript arrow in that same slot with one explicit Transcribe/Retry icon; failed Retry is red. Uploading shows disabled busy feedback. The accessible action label has no visible cost prose. Existing received-but-unsaved text still offers its local save action rather than another HTTP request. Text-only Live messages never pretend to have an audio file.

This follows the approved Soft Current composition. The explicit audio-only/expanded-text toggle is the later Telegram-reference clarification, not a feature claimed to exist in the original board. No reference message content or reference screenshot is shipped.

The former main editor belongs to its current history message. A read-only source-ID accessor preserves the existing session/storage ownership; UI does not rewrite the record ledger to move an editor. Edited main text overrides that message's displayed original transcript and remains editable/copyable there. Unlinked retained text has an explicit Current text bubble, also after Activity recreation. Shared bubble recovery can read the persisted edited/unlinked draft without retaining an old target editor. Clear current text preserves saved recordings; confirmed Delete still removes its associated saved draft. Temporary empty edits retain their actual source ID; only explicit Clear detaches the current draft. An in-memory edit whose disk commit failed remains copyable after history dismissal, backgrounding and recreation, with the same generic error. Refresh does not reload older disk text over it; a confirmed source deletion still invalidates it. A deleted source never becomes a new fallback draft.

Waveforms are read-only local thumbnails, sampled at 40 evenly spaced positions. Canonical 16-bit PCM WAV uses bounded direct file reads (up to 512 frames per position); extended layouts and compressed formats use MediaExtractor/MediaCodec. AAC uses one decoder run for forty two-frame windows: the first real frame restores overlap history and the second supplies the measured peak. This avoids forty costly decoder flushes without decoding an entire long recording. Work runs on IO, serially, with cancellation checks, an eight-second work deadline and independently released resources. A compressed sample may straddle its target time; the final valid frame of a short AAC clip is retained instead of requiring a nonexistent later frame. A 16-entry process-memory cache contains only successful thumbnails; transient failures are not negatively cached, so a later explicit opening can try again. It never evicts audio or text. Missing/unsupported audio or a thumbnail timeout renders a neutral transport track rather than invented voice peaks. Waveform inspection has no microphone, credential, editor or HTTP dependency.

Holding the idle keyboard bubble opens the same sheet in its own activity. No editor identity travels to history. Explicit retry returns a passive result and never inserts into an old field. Cards read the durable RecordingRepository, newest first, with date separators. No startup/reconnect upload, automatic retry, retention policy or eviction is added. Successful audio and text remain until explicit Delete. Interrupted audio may be incomplete; decoder failure preserves its original bytes.

Playback retains its separate generation-checked owner and Android MediaPlayer adapter. Closing the sheet/activity, backgrounding, deletion, retry, audio-focus loss and every actual Record microphone start stop and release playback. Pausing abandons audio focus. Reading a transcript or waveform never starts playback or a network call.

The LazyColumn remains scrollable for long history and long expanded text. Text selection and editing are explicit, all icon actions retain accessible names and minimum touch targets, and controls remain reachable at large font. Expansion and progress use the existing motion-duration preference.

Runtime screenshots, reference comparisons, machine checks and delivery reports stay outside Git. Synthetic test audio/text and a localhost fixture are not evidence of real-device acoustics, first-word latency, OEM compatibility or live OpenAI service quality. No paid API calls are part of validation.
