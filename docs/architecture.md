# Record architecture

`DictationSession` owns local recording, one explicit Stop upload, manual retry, timer/cancel/close, encrypted-key state and durable draft checkpoints. It has no mode, PCM source, realtime events or WebSocket port. Its generation token prevents late uploads/safety callbacks from affecting a new owner. Record starts before key loading/network readiness; Stop waits for an existing local key operation without opening another request. Retained failures require an explicit retry.

`DictationSessions` composes fresh `DeferredAudioRecorder`/`AndroidAudioRecorder` owners, the shared HTTP file transcriber and serialized encrypted key store. The repository owns durable audio/text, count capacity and upload claims; session/editor/credentials never enter persisted history. See [storage](durable-recordings.md), [history](recording-history.md), [capacity](history-count-limit.md) and [legacy compatibility](record-only.md).

`MainActivity`/`DictationViewModel` adapt lifecycle/permission events and render the stateless main UI. The adaptive root keeps dictation/history in stable pane slots, retains recording across configuration recreation, and keeps onboarding in one themed safe region; see [adaptive policy and lifecycle](adaptive-history.md). The focused [setup flow](onboarding.md) stages key candidates until encrypted persistence succeeds; failure or deferral cannot turn a discarded candidate into a transcription credential. Existing intentional Settings keys retain their explicit Save behavior.

`FloatingCapture` validates the captured original editor, visibility, lock, keyboard and permissions immediately before starting the same Record session. `FloatingDictationService` retains its notification/environment ownership. `FinalTextInsertion` remains shared by Record: one final result, one attempt on the original connection, environmental revalidation after suspended reads, no retarget, rollback, full-field replacement or Send. Retry/history never receive an editor token. API26–32 unsupported insertion offers Copy; conservative field policy remains unchanged.

`CurrentDrawable` supplies common state colors/calm motion and a local, transient PCM-driven nine-region spectrum during recording. `AndroidAudioRecorder` owns a single AudioRecord → AAC-LC MediaCodec → M4A MediaMuxer path, shared by main and overlay; the renderer never owns a microphone. See [signal/capture lifecycle and acceptance](audio-reactive-current.md). The setup preview uses the actual same idle renderer with no action callback. Shared accessibility live regions and stored-audio PCM waveform decoding remain; they are unrelated to the removed Live transport.

Debug-only opt-in uses a separate synthetic credential namespace and a localhost HTTP fixture. Release builds retain no fixture endpoint entrypoint. Tests and screenshots must distinguish source/JVM/compilation from actual Android execution. No paid provider requests are part of the checks.
