# Adaptive main and history

Layout uses the **current inset-safe app window**, including resize/multi-window, not a phone model, screen size or folded flag. When both panes fit (**616 dp** available width at ordinary font scale), dictation stays left and the existing message history is persistent on the right. Below that boundary the saved-count entrance/swipe opens the same bottom sheet. No second repository, upload flow or history design is introduced. Settings remains in the main workspace slot. Onboarding is a separate cohesive presentation: it uses the full safe area with centered readable-width content and never composes a history pane or sheet. A reported separating hinge still limits setup to one unobstructed region.

The threshold is content-based: `280 × max(1, fontScale)` dp for dictation and `320 × max(1, fontScale)` dp for history, plus 16 dp spacing. The earlier 840 dp expanded-class cutoff incorrectly excluded usable medium windows, including unfolded portrait inner displays; it is removed. Thus large fonts can deliberately select the compact layout even in a broad window. Without a relevant reported fold, history receives about 46% of the width, bounded by those minima. Both panes scroll independently and respond to height/IME/insets; orientation alone selects nothing.

One focused `androidx.window:window:1.5.1` dependency supplies real `FoldingFeature` information. A reported vertical fold, including FLAT, replaces the ordinary gap if both sides independently fit; otherwise the app uses the larger unobstructed side with the compact sheet. This reserves stable book-layout geometry before HALF_OPENED instead of abruptly resizing and relocating dictation on a posture-only event. A flat horizontal crease does not reserve space; separation or actual FULL occlusion does. A horizontal separating fold uses the larger unobstructed top/bottom region. Hinge coordinates are translated from window pixels to the actual safe content bounds; no controls are intentionally placed across a separating fold. If the device supplies no hinge information, ordinary width adaptation still works. No new permission is required. Delete and limit dialogs use the same safe slot region (history on the right, Settings on the left), intersected with current dialog insets/IME. Their scrollable content and buttons are never deliberately centered across a reported separating hinge.

## State and lifecycle

The main composition remains in one scaffold body while its bounds change, preserving Settings, onboarding draft/flow and scroll. The root Surface paints the full window before insets are applied, so pane spacing, margins and system-bar underlays follow the active Material theme. Day/night Activity resources supply matching window backgrounds and system icon attributes before Compose draws. No global dark-theme override is introduced. History shares one `HistoryUiState`: list position, expanded message IDs, current-text expansion, menu/confirmation identity and limit dialog. Saved UI state includes identifiers/positions and unfinished Words input; transcript and credentials remain in existing session/storage owners. Message content and actions are the same implementation in both presentations.

An Activity-retained `HistoryViewModel` owns the single player and explicit retry jobs. Moving sheet ↔ pane does not restart playback, duplicate HTTP or cancel a submitted retry. Configuration recreation retains this owner and the dictation ViewModel; `MainActivity.onStop` only backgrounds the recording session when actually leaving, not during configuration changes. Actual background, explicit sheet dismissal, deletion/retry, focus loss or microphone start release playback as before. No process-death playback/recording continuation is promised: durable recovery remains the existing explicit workflow.

There is exactly one history presentation. Compact uses a standard Material3 `BottomSheetScaffold`: the visible handle/count and revealed content belong to the same surface, which tracks vertical drag and settles by the standard distance/velocity rules. There is no second collapsed card, modal window or scrim. Nested list scrolling hands downward motion to the sheet when the list reaches its top; tap/accessibility and Back remain alternatives. Wide layout keeps the persistent right pane. If compact was open before widening, it returns open when narrowed; a resize during drag retains the standard target anchor. Pending delete/limit dialogs transfer with their state and receive Back before the drawer. No visible History/Close heading or swipe instruction is added.

The main composition stays in one `BottomSheetScaffold` body at all widths, retaining Settings/session UI. In wide/setup/Settings presentations its drawer has zero peek, no handle/content, gestures or Back handler; history is composed only in its visible slot. This avoids moving an AndroidView-bearing composition into/out of Material subcomposition, which failed during teardown after repeated width/font changes in the API28 stress test. Sheet state and History/Words input/list state are held above the compact/wide branch. Full collapse clears transient menus/focus and stops playback; ordinary resizing does not. Hidden compact content does not decode history waveforms. Insets/IME constrain the host to the same safe region; an exceptionally short Words viewport can scroll its inline form so Add remains reachable. Material owns drag/nested-scroll/settling and uses the platform animation duration scale; no custom gesture physics or decorative microphone analysis is introduced.

See [fold posture regression](fold-posture.md) for the reproduced synthetic failure, stable geometry, tradeoffs and device acceptance.

## Verification

Pure policy tests cover 615.99/616 dp, medium-window regressions at 700/704/839/840 dp, larger font, usable/unusable vertical hinges, tabletop, off-window features and zero-size transitions. Compiled Compose tests cover sheet/pane resizing, one content instance, expanded edited draft, Settings continuity, saved UI restoration, shared scroll and pending deletion. An Activity test recreates during Record and transcription and asserts a single request. These Android tests require a functioning device; compilation alone is not runtime evidence.

R02 verification uses the API28 software emulator without KVM. Three focused Compose pointer scenarios ran successfully: movement before release/settling/tap, nested list-to-drawer scroll, and Words input plus compact/wide transfer with main-state retention. The confirmation/Back scenario hit RootViewWithoutFocusException while the existing System UI ANR owned window focus; it is not claimed passed. Full UI/physical hinge validation remains separate. Actual headless collapsed/intermediate/expanded component renders use a deterministic injected intermediate offset, which is not gesture proof. Exact heads, terminal command outcomes and CI are recorded in the PR. No paid provider requests are used by tests.

References: [window size classes](https://developer.android.com/develop/adaptive-apps/guides/use-window-size-classes), [canonical layouts](https://developer.android.com/develop/adaptive-apps/guides/canonical-layouts), [fold-aware Compose](https://developer.android.com/develop/ui/compose/layouts/adaptive/foldables/make-your-app-fold-aware), [WindowManager stable release](https://developer.android.com/jetpack/androidx/releases/window).

## Onboarding/theme regression

Only the normal dictation/history workspace uses two panes. First-run and manually opened setup stay centered as one screen at any usable width, with no history beside them. Deferring setup restores the appropriate workspace presentation. Opening the guide releases hidden playback; explicit retry ownership remains retained. The disclosure dialog uses the same hinge-safe themed dialog host.

Android regression tests compile cohesive setup/resize/draft/defer transitions, dark/light root corner pixels, and day/night XML window/bar attributes. Headless rendering must use the real app theme and the actual adaptive root without an extra outer Surface that would conceal missing background paint. Neither rendered components nor compiled tests establish a physical-device runtime pass.

## Ручная приёмка

1. Установить обновление поверх существующего приложения: история, ключ, лимит и положение floating button сохраняются. Открыть маленькое окно: снизу только количество записей; tap/swipe открывает историю, Back/drag закрывает.
2. Расширить окно до ≥616 dp при обычном шрифте: диктовка слева, история справа постоянно; нижнего входа и scrim нет. Сузить окно: история снова доступна снизу. Повторить в landscape и split-screen; размер устройства сам по себе не должен включать две панели.
3. Раскрыть длинный transcript, отредактировать текущий текст, прокрутить историю; несколько раз сложить/разложить и изменить ширину. Текст/раскрытие/позиция и открытые Settings сохраняются. При шрифте 200% допускается компактный режим ради читаемости.
4. Открыть Delete и изменить ширину до подтверждения: один диалог, Cancel не удаляет, Delete удаляет только выбранную запись. Повторить с лимитом истории и открытой клавиатурой.
5. Включить аудио, изменить ширину и повернуть экран: воспроизведение продолжается там, где аудиофокус ОС позволяет. Pause/смена записи работают. Закрытие компактной истории, Home, Retry/Delete и начало Record освобождают плеер.
6. Начать офлайн Record, изменить ширину/повернуть экран, затем Stop: одна сохранённая запись. Без ключа нет HTTP. При synthetic/local fixture или собственной готовой конфигурации повторить во время transcription: один запрос, без повторной вставки/автоповтора.
7. На устройстве с разделяющим шарниром проверить обычную/книжную/tabletop позиции: кнопки не пересекают шарнир; при тесных половинах одна безопасная область и sheet. Нет обещания проверки конкретной OEM-модели без её фактического запуска.
8. Проверить Play/Pause, раскрытие/Copy, явный Retry, подтверждаемое Delete, заполненный лимит и старые текстовые записи. Нет Live-переключателя, автоудаления или автозагрузки.

9. Включить системную тёмную тему: onboarding на раскрытом экране один, по центру, без истории. Фон, поля вокруг карточек, зазор и область статус-бара тёмные. Изменить ширину и повернуть экран: шаг/введённый staged-текст не сбрасываются. **Not now** открывает main с историей справа при достаточной ширине. Проверить пустую/заполненную историю, затем светлую тему и повторное открытие guide из Settings.

10. С ключом ещё не настроенным: **Not now** → открыть историю в узком окне → расширить → **Settings → Paste** с синтетическим кандидатом. Guide должен открыться одним экраном без истории; кандидат только staged, не сохранён и не отправлен. Повернуть экран, затем **Not now** и сузить: нет скрытого sheet/scrim и самопроизвольного повторного открытия.
