# Signed APK worker (prepared, disabled until owner acceptance)

This replaces neither existing installs nor draft PR #17 automatically. The new workflow is inert while repository variables `APK_RELEASES_ENABLED` and `APK_PR_BUILDS_ENABLED` are unset/other than the exact string `true`. This PR does not create secrets, Environments, a ledger branch, a tag or a Release. Ordinary Android CI needs no signing material. See [local key creation and the deliberate reinstall boundary](signing-key.md).

## Distribution contract

Every **first-parent commit on main after an explicit bootstrap anchor** gets one stable patch SemVer Release, oldest first (`0.19.2` → `0.19.3` → `0.19.4`, unless the owner deliberately chooses a different baseline before initialization). A linear multi-commit push includes all its mainline commits; a merge is one mainline commit, not separate releases for every side-branch ancestor. Source SHA and controller SHA are pinned independently. Commit messages do not choose versions. Ordinary source `versionName`/`versionCode` remain local-build defaults; a trusted Gradle init overlay injects the ledger allocation and disables Gradle signing for the release build. Distribution license assets are explicitly overlaid from the trusted controller revision, including for compatible older PRs.

The manual `pr` operation accepts an open PR number targeting main, pins its current full head SHA and produces an APK artifact without publishing a Release or inserting anything into the PR. Only the canonical personal repository owner's immutable actor ID may execute PR/restore/initialization; both original actor and rerun actor are checked. Other writers may still see GitHub's Run workflow button; execution is rejected. A repository transfer/owner rename requires a reviewed policy update. Owner-authorized test execution does **not** make an APK safe: reviewers must inspect untrusted changes before installing.

One global, serialized allocation/build/sign/publication workflow is shared by stable, PR and `restore-main`. Every attempted build consumes a strictly increasing Android `versionCode`; failures leave gaps and never recycle numbers. The maximum is 2,100,000,000. PR names use `<stable>-pr.<number>.<code>`; a later stable gets a higher code. **An already downloaded older stable APK cannot update a newer PR APK.** Owner operation `restore-main` rebuilds the latest fully released main with a fresh higher code, name `<stable>+main.<code>` and a downloadable artifact, without creating another stable Release. It refuses a pending stable backlog. No Android downgrade promise is made. Strict monotonicity assumes no out-of-band signing/distribution, no ledger reset/force-push/deletion, and trusted main/controller administrators.

## Why commits are not silently skipped

GitHub [concurrency](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/control-workflow-concurrency) normally replaces a pending run, even with `cancel-in-progress:false`; the optional `queue:max` holds at most 100 pending runs and cancels overflow. This worker deliberately uses the broadly supported default coalescing queue, with no event-per-release assumption. A [push payload](https://docs.github.com/en/webhooks/webhook-events-and-payloads#push) can contain multiple commits and has payload limits. Neither is the release ledger. A coalesced manual PR request can be dispatched again by the owner; automatic main work remains durable in the Git graph/ledger.

Each worker fetches full first-parent main history and compares it with `release-ledger/ledger.json`. It reserves **one oldest unfinished commit**, runs its checks/build and publishes it, then wakes another worker if needed. A failed commit blocks subsequent stable commits instead of disappearing. Successful self-dispatch uses the documented [`workflow_dispatch` exception to GITHUB_TOKEN event suppression](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/trigger-a-workflow). Hourly reconciliation and an owner manual `reconcile` recover canceled/overflowed/coalesced push wake-ups, lost continuations and expired attempts. The ledger is updated with a non-forced Git ref compare-and-swap; concurrent updates cannot both win. A capacity bound stops rather than truncates the ledger.

Published releases are recovered from their bound source/tag/allocation marker if publication succeeded before the ledger acknowledgement failed. Repeated wakes do not create a duplicate release. A retry of an unpublished attempt burns its old code and gets a higher one. Partial bound drafts may have their draft assets replaced; published releases/tags are never overwritten/moved. An unrelated tag/release, rewritten main history, changed controller or changed certificate stops the worker. Rerun **all jobs** or dispatch a fresh reconcile; rerunning only failed jobs is refused by run-attempt checks. Queued old controllers stop when executable release code changes, so a current worker can recover with the reviewed controller.

This is eventual catch-up while Actions, permissions, approvals and builds work, **not a delivery-time or unlimited-queue guarantee**. GitHub rate/queue/runtime/storage limits, disabled scheduled workflows (including inactivity policy), failed builds and unapproved environments can block progress. Inspect failures and use manual reconcile after fixing their cause; never skip a commit/reset the counter as a shortcut. Historical commits before the explicit anchor are not retroactively released. State currently has a 900 KB safety cap; a reviewed archival migration must preserve cursor, identity, allocation high-water mark and recovery records before exceeding it.

## Isolation and trust boundary

The workflow exists on `main`; dispatching it on a PR branch is refused. It never uses `pull_request_target` or `workflow_run` to execute PR code with secrets.

| Job | Inputs/execution | Authority |
| --- | --- | --- |
| plan | Trusted controller, Git graph and ledger; pin PR SHA | Contents write for ledger, PR read; no signing environment |
| build | Exact source, Gradle/checks; isolated dependency home | Contents read, no key, environment or shared cache |
| validate | Trusted code; bounded fixed-member artifact extraction, aapt/zipalign and metadata checks | Key-free fresh VM, Actions/contents read |
| sign | Trusted controller and exact validated artifact ID + SHA-256 from validate job outputs | Protected environment; contents/Actions read, no publication write |
| publish | Exact signed artifact ID + SHA-256, full certificate/package/version/source/license/alignment verification | Fresh key-free VM, contents write |
| wake-next | Trusted controller checks backlog, dispatches next wake | Actions write, contents read; no key |

Artifact names alone do not authenticate a producer: build code can access a run-scoped upload token. The private-key job therefore verifies immutable ID **and ZIP digest from the trusted validate job**, and publish does the same for sign. Source bytes remain untrusted until validation. Extraction accepts only fixed expected filenames and enforces count/size/type limits. No Gradle, dependency download, source executable, aapt or APK archive extraction runs in the signing step. Actions are commit-pinned. Passwords are environment references, never CLI literals; private temp files have `0600` access and are cleaned on normal/error exits. Runner destruction is the fallback for abrupt termination. A small apksigner/keytool/JDK/runner parser/toolchain attack surface remains; binary checks and revision metadata are **not reproducible source provenance**. Trust main protection, upstream pinned tools and environment administrators. No paid API or dictation request is part of these jobs.

This public repository's Actions artifacts/logs and final stable Releases are publicly readable under GitHub's access rules. Owner-only dispatch is an execution restriction, **not private test-APK distribution**. Internal unsigned/validated/signed artifacts expire after one day; final APK artifacts after 14 days. Only a final verified artifact or published Release is a distribution candidate.

## Owner setup and readiness checklist

Do this only after reviewing/merging the pipeline and separately agreeing to controlled activation. No assistant action has configured these settings.

1. Protect `main` against force pushes/deletion and unreviewed changes, especially workflows/controller scripts. Protect the future `release-ledger` branch against deletion/force pushes; allow the workflow's normal fast-forward updates without impossible required PR/check rules. It is an orphan bookkeeping branch, not app source. Back it up securely. Do not recreate it automatically if missing. Choose a new explicit recovery high-water mark through a reviewed procedure if it is ever lost; disabling the worker is safer than reusing codes.
2. Generate/backup the new local key using [signing-key.md](signing-key.md). Do not use the legacy cloud debug key. Record the public fingerprint and set repository **variable** `APK_SIGNING_CERT_SHA256` (64 lowercase hex characters). It is a fingerprint, not the private key.
3. Create **`apk-stable-signing`** and **`apk-pr-signing`** Environments. For **both**, use selected deployment **branches** → exactly `main` (not matching tags, not “all branches”, not merely “protected branches”, which can allow all when no branch rules exist). Disable administrator bypass. GitHub [environment rules](https://docs.github.com/en/actions/reference/workflows-and-actions/deployments-and-environments) and plan availability must be verified in the repository UI.
4. For `apk-pr-signing`, require reviewer **IlyasYOY**. The single-owner setup must allow self-review so the owner can approve their own dispatch. Inspect pinned PR/source SHA and allocation before approval. For stable automatic releases, no manual required reviewer: adding one intentionally makes every stable release wait for a human. A branch restriction still applies.
5. Add **only Environment secrets**, in both environments: `APK_SIGNING_KEYSTORE_BASE64`, `APK_SIGNING_STORE_PASSWORD`, `APK_SIGNING_KEY_PASSWORD`. Add Environment **variable** `APK_SIGNING_KEY_ALIAS=voice-dictation`. The PKCS12 creator uses the same password for store/key. Keep GitHub's token separate; no personal access token is needed. See the local stdin-based commands; never put these values into repository/organization secrets accessible to untrusted workflow code.
6. Leave **both enable variables unset/false**. Run the trusted workflow on branch **main**, operation **initialize** once, with `start_after` = deliberately selected full first-parent SHA, base SemVer `0.19.2`, and floor at least **42** or the highest versionCode distributed anywhere if larger. Releases begin **after** that SHA. Initialization pins the new certificate, never overwrites an existing ledger, and refuses repositories with existing Releases/version tags; that case needs a separately reviewed migration. It is not disaster recovery. If the goal is to release the pipeline merge commit itself, choose its first parent as the anchor. Do not accidentally request the whole historical repository.
7. Separately agree readiness for a controlled test. Set `APK_PR_BUILDS_ENABLED=true`, keep `APK_RELEASES_ENABLED` false. Owner dispatches operation `pr`, specifies a reviewed open PR targeting main, approves the environment and checks final metadata/certificate. This is a real signature, so it is outside this PR's unprivileged local tests. Test a fresh install (legacy install must first be preserved/exported then removed) and a second new-key build with a greater code using `adb install -r`. Confirm retained history/settings and normal app behavior. Mac-only key generation has not been executed by this cloud task; see explicit validation evidence in the PR.
8. After separate stable-publication readiness agreement, set `APK_RELEASES_ENABLED=true`. Owner dispatches `reconcile` or the next push/hourly wake starts catch-up. Verify first Release source/tag, SemVer, cert, code, uploaded digest and advanced ledger. Verify a linear two-commit push/fast consecutive pushes in a controlled repository before relying on the catch-up policy. Observe failures, continuation and manual recovery. These live operations are **not** implied by merging preparation code.
9. To pause, set the flags false and cancel an in-flight worker explicitly. Flags changed during a running job are not a real-time revocation mechanism; a job may have captured prior values. Cancel jobs before changing key/controller protection. Do not remove/recreate ledger or delete published tags as a pause mechanism.

Normal CI executes Python offline ledger/archive/key-script tests, Android build/lint/JVM checks and compiles UI tests without signing secrets. It does not prove real protected-environment configuration, hosted artifact transfer, release upload/recovery or Mac compatibility. Before activation those need the controlled tests above. Cloud artifact storage access has previously been denied; no workaround or private credential transfer is part of this implementation. The earlier publication audit's unavailable historical logs/artifacts remain a separate limitation.
