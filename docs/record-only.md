# Один сценарий записи

Новый захват всегда Record. Удалены mode selector, исполнительный enum режима, PCM capture worker, realtime/WebSocket transport, потоковые события/сборка partial-транскрипта и соответствующие debug entrypoints. Остаются HTTP file transcription через существующий `gpt-transcribe`, безопасная однократная вставка готового результата, waveform-декодирование сохранённого аудио и общий renderer состояний. Общие HTTP/JSON зависимости остаются нужны Record; PCM-декодирование в waveform не является Live capture.

## Обновление

`dictation_mode.explicit_mode` больше нигде не читается для выбора поведения. При запуске удаляется только этот устаревший ключ предпочтения, независимо от старого LIVE/RECORD/default/неизвестного типа; другие настройки, ключ, режимы доступа, лимит и положение кнопки не очищаются. Даже отказ записи этого необязательного cleanup не может вернуть удалённый исполнительный путь.

Формат `recordings-v1` сохраняется. Старое metadata `kind=LIVE` декодируется только в read-only `LEGACY_TEXT`; новые строки создаются только как RECORD. При обслуживании старой строки сохраняется прежнее wire-значение, поэтому текст и partial/status не теряются. История показывает «Text only», без Play/Retry и выдуманного аудио, с раскрытием/Copy и подтверждаемым Delete. Связанные main/floating черновики остаются читаемыми; удаление строки инвалидирует связанный черновик как прежде.

Старые незаполненные admission/reservation были только памятью процесса и не переносились на диск. Обновление/новый процесс их не восстанавливает. Любая уже созданная непустая директория/commit/staging bytes сохраняется и учитывается в счётчике; неизвестная metadata остаётся UNAVAILABLE. Уже сохранённый текст, аудио и записи сверх выбранного лимита не удаляются. Активный Record учитывается своей CAPTURING-строкой до микрофона; два владельца не могут взять последнее место одновременно.

Ни чтение, ни обновление/миграция не отправляют запросы. Старые текстовые строки исключены из pending audio. Retry аудио остаётся явным, а восстановление результата не имеет старого editor token и не вставляет текст повторно.

## Проверка

JVM покрывает raw old-format text/audio metadata, draft links, подсчёт/лимит/рестарт, сохранение staging failures, офлайн-захват, Stop/retry и безопасность единственной финальной вставки. Android-проверки включают очистку старого preference, отсутствие selector и историю текстовых записей; исполнение требует стабильного устройства. В текущей среде Android/KVM недоступен после исчерпанных системных сбоев, поэтому новые скриншоты/runtime pass не заявляются.
