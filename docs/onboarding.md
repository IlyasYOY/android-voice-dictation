# First-run setup (VD011)

Setup shows one missing step: API key, microphone, then the optional keyboard button and its permissions. Existing users with a loaded key and all permissions for their chosen capabilities enter the main screen directly. Key presence is checked locally; launching or resuming never validates a key with the provider.

**Not now** defers the whole guide for the current visit and allows offline Record and stored-history access. Rotation, an app-launched browser/settings round trip, and a permission dialog continue that visit. A normal background/reopen or a fresh process starts a new visit and offers reliably missing setup again. Optional floating opt-out is remembered. Settings offers the guide when something remains missing. Recording capability remains separate from transcription readiness.

The key field is masked. Paste reads a single plain-text clipboard item only after a focused foreground tap, only while no key/candidate exists, and accepts a conservative `sk-` candidate. It never coerces a URI or reads on browser return. A pasted or typed onboarding candidate stays in ViewModel memory through rotation, is absent from saved instance state, and is discarded on deferral or process loss. **Save and continue** is a separate confirmation before the existing encrypted key store receives it. A save failure leaves the guide on the key step. The candidate is never promoted to the session credential while persistence is pending or after failure. Deferring drops the field without rolling back any independently edited Settings key. If the already explicit Save later succeeds, that successfully persisted key is preserved; failure cannot leave the discarded candidate active for Record/Stop. Existing saved keys are never overwritten by Paste. A failed initial store read is treated as unknown, not absent: onboarding input/Paste/Save remain disabled, while Not now allows offline access and Settings keeps the deliberate Forget control available. Only a successful read, Save or explicit Forget resolves that uncertainty. Manual typing in Settings retains its existing explicit Save behavior.

Microphone, enabled accessibility service and notification/channel permissions are observed again on resume. Permission prompts and navigation happen only after a tap, with a guard against duplicates. A permanently denied runtime permission leads to app settings. The floating button remains optional; the existing accessibility disclosure precedes enabling it. Notification readiness follows the existing floating-service requirement for visible Stop/Cancel controls.

Manufacturer background/autostart restrictions cannot be observed reliably. The guide explains this once after the floating prerequisites, records only a successful acknowledgement, and leaves the app-settings control available in Floating settings. It never reports this acknowledgement as a grant. Already configured installations are not interrupted by this optional explanation; they can open it through the guide.

Only nonsecret versioned setup metadata is stored in `onboarding_v1`: prior visit, optional choice, explanation acknowledgement, permission-request flags and legacy migration state. Required deferral is deliberately not persisted. No history, bubble position, recording, key-encryption or retry policy is changed.

## Verification

JVM tests cover migration, re-entry/deferral, denial/cancel, missing/revoked grants, duplicate actions, metadata validation/failure, explicit lazy clipboard access and staged key lifecycle. Android tests separately cover real metadata commits and Compose/activity lifecycle using synthetic key stores/grant observations. The explicit-paste Android test uses only a synthetic clipboard value and requires actual app input focus; this is not proof of provider access or every OEM's permission screens. Existing feature tests explicitly defer setup or use an in-process test-only bypass so their original scenarios remain focused.

## Floating button settings

The later Floating button screen uses the same setup layout, card and primary action as first run. Back is navigation. On/Off reflects the user's floating-capability choice; grant readiness is determined separately from actual platform observations. After explicit opt-in and the full Accessibility disclosure, it offers only the first missing prerequisite in the same order: microphone, Accessibility, recording notifications. Completed grants have no redundant buttons. A permanent runtime denial opens the relevant settings screen; notification-channel blocking opens that channel, rather than unrelated generic settings.

Turn off remains a secondary explicit action, preserves saved data and position, and asks the connected Accessibility service to revoke itself. If it cannot do so because no service instance exists, Android Accessibility settings provide the deliberate revoke control. An Off capability with a still-observed service grant exposes Revoke access until the observation changes. Revocation is not claimed optimistically. More contains the full access disclosure and the later OEM background-help control. Unknown OEM restrictions stay a one-time acknowledgement, not a permission status. Saved audio/text recovery actions remain available when recovery data exists.

The two setup hosts merge monotonic nonsecret metadata before writes and on return, so an acknowledgement or permission-request flag from one host is not overwritten by the other. UI and policy tests cover the quiet enabled state, sequential missing grants, explicit disable/consent/re-enable, pending requests through rotation, denial/settings navigation, Back, and shared acknowledgement. Android runtime/screenshot evidence must be reported separately from test compilation.

The floating setup illustration is the actual shared `CurrentDrawable` through `CurrentMarkView`, at the overlay's idle 64dp size and 3dp inset. It is a decorative preview with no button semantics or recorder/network/navigation callback. It keeps the existing renderer's idle/reduced-motion behavior rather than adding a separate microphone icon or spinner.
